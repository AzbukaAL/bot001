# Капитан Сэм — проект ответа на претензию покупателя

Система принимает претензию покупателя (текст или файл PDF/DOCX/ODT, один или несколько пунктов) и документы
проекта (КП, опросный лист, теплотехнический расчёт) и готовит **проект ответа** со ссылками на нормы
(СП, ГОСТ) и стандарт компании. Каждый пункт получает вердикт и маршрут: ответ покупателю (файл DOCX)
или черновик инженеру с заготовкой и причиной. Продукт — «проект ответа + проверка человеком»,
окончательное решение всегда за инженером компании.

Интерфейс — боты MAX и Telegram (один обработчик). Правила проекта, журнал решений и открытые вопросы —
в `CLAUDE.md`.

## Как устроен ответ

1. Претензия разбивается на пункты (`src/claim_doc.py` для файлов), текст **обезличивается**
   (`src/anonymize.py`): ФИО, телефоны, адреса, паспортные данные заменяются метками до любого вызова модели.
2. Поиск оснований по индексу норм (BM25, `src/run08.py`) и по индексу стандарта компании
   (`src/reglament_index.py`); данные объекта — из документов проекта (`src/project_docs.py`, `src/object_index.py`).
3. Расчёты, где они нужны, делает код, а не модель: электрика (`src/calc_electric.py`), теплотехника —
   ГСОП и требуемое сопротивление теплопередаче по СП 131 и СП 50 (`src/calc_teplo.py`, `src/climate_sp131.py`).
4. Генерация ответа и проверка (`src/answer.py`): вердикт, сверка цитат с текстом нормы по фактам,
   судья «цитата не за покупателя»; не прошедший проверку пункт уходит инженеру.
5. Оформление DOCX (`src/answer_docx.py`), сводка по вердиктам, отправка в бот (`src/bot_max.py`, `src/bot_tg.py`).

Модели вызываются по **ролям** (`config/llm_roles.json`: `mechanical`, `language`); имён моделей в коде нет.

## Состав репозитория

| Путь | Что это |
|---|---|
| `src/` | ядро: обработчик, обезличивание, индексы, расчёты, боты; `src/test_*.py` — тесты без вызовов модели |
| `src/run0*.py`, `src/mvp_*.py`, `src/etalon*.py`, `src/eval_verdict.py` | прогоны и сверка с эталоном при разработке (история, на работу бота не влияют) |
| `config.example.json` | настройки бота без личных данных (копируется в `config.json`) |
| `config/llm_roles.json` | модель для каждой роли |
| `deploy/` | юниты systemd: боты и ежедневный отчёт о расходе |
| `materials/` | **материалы заказчика — только на сервере, в git нет**: нормы (`normy/`), стандарт компании (`reglament/`), документы объектов (`objects/`), разборы (`razbory/`) |
| `build/` | **результаты — только на сервере, в git нет**: индексы, OCR, разборы обращений, журнал вызовов модели, выдачи DOCX |
| `COMPONENTS.md` | перечень ядра и сторонних компонентов с лицензиями |

## Запуск

Сервер: Ubuntu 24.04, Python 3.12. Зависимости:

```
apt install poppler-utils tesseract-ocr tesseract-ocr-rus
pip install python-docx pdfplumber beautifulsoup4
```

Индексы (после загрузки материалов в `materials/`):

```
python3 src/ocr_scans.py                 # сканы норм без текстового слоя → build/ocr/
python3 src/normy_parse.py               # индекс норм v1 (бот) + таблицы СП 131 построчно
python3 src/normy_parse.py --v2          # индекс v2 (полные тексты)
python3 src/reglament_extract.py && python3 src/reglament_index.py   # стандарт компании
```

Боты и отчёт о расходе:

```
cp deploy/*.service deploy/*.timer /etc/systemd/system/ && systemctl daemon-reload
systemctl enable --now captain-sam-bot captain-sam-tg captain-sam-cost.timer
python3 src/bot_max.py --emulate файл.txt   # локальный эмулятор без бота: текст → DOCX
```

Тесты (без сети и без вызовов модели; последняя строка каждого — `имя: ok/всего` или `ПРОВАЛ`):

```
for t in src/test_*.py; do python3 "$t" | tail -1; done
```

## Конфигурация (без секретов)

- `config.example.json` → скопировать в `config.json`: `max_claims_per_message` — лимит пунктов;
  `claim_met_by_standard`, `quote_verified` — правила вердикта (пояснения в ключах `_…`); `max_api` — адрес API MAX.
- `config/llm_roles.json`: модель роли; переопределяется переменной окружения `LLM_MODEL_<РОЛЬ>`.
  Роль без модели — ошибка при запуске, а не модель по умолчанию.
- Секреты и личные идентификаторы — **только в `.env` в корне проекта** (права 600, в git не попадает; читает
  `src/env_file.py`): `POLZA_API_KEY` — ключ API модели; `MAX_BOT_TOKEN` — токен бота MAX; `TG_ADMIN_ID`,
  `TG_BOT_USERNAME` — администратор и имя бота Telegram; `SETTINGS_USERS` — кто меняет тон и иронию командами
  `/тон`, `/ирония`, `/настройки` (id через запятую); `MAX_ALLOWED_USERS` — кому отвечает бот MAX (чужим — «доступ закрыт»).
  Токен бота Telegram — строка `TG_BOT_TOKEN=` в файле, путь задаётся `CS_TG_ENV`. Нет токена — бот не падает, проверяет файл раз в 60 с.
- Переменные `CS_MAX_API`, `CS_TG_API`, `CS_*_ACCESS`, `CS_*_KP`, `CS_ENV_FILE` — только для тестов на поддельном API.

## Правила по данным

- Персональные данные покупателей (ФИО, телефоны, адреса, паспорт) не передаются модели: обезличивание
  в `src/anonymize.py` стоит до каждого вызова; в журналы пишутся только счётчики.
- Новый тип документа сначала проходит `python3 src/pdn_check.py <файл>` (счётчики и слова вне словаря, без текста).
- Материалы заказчика и результаты (`materials/`, `build/`) в git не попадают (`.gitignore`).
